## 1. Grok Bot 能做什么

Grok Bot 的核心单位是 **Bot**：每个 Bot 有自己的名称、职责、对话和逐渐积累的工作上下文。你通过对话给它任务，它可以在持续运行的云端电脑上使用浏览器、文件系统、命令行和已连接的应用处理多步骤工作。任务可在后台继续，即使你关闭笔记本也不会因此停止。[官方产品概览](https://docs.x.ai/grok-bot/overview)

可以把它用于整理报告、读取业务资料、查找网页信息、生成文件、分析代码或准备周期性简报。建议先从“研究、整理、草拟”开始；发送、发布、购买、删除或修改生产系统等外部动作，明确要求它先停下来等你审核。

## 2. 开始使用与创建 Bot

### 使用前准备

根据官方套餐说明，当前访问方式包括付费 Cursor 个人方案或 Cursor Teams；将 SuperGrok、SuperGrok Plus、SuperGrok Heavy 或 X Premium+ 个人订阅关联到 Cursor 账户；或使用拥有自助式 Grok Business 已分配席位的 Grok 账户登录。Grok Bot 提供 macOS、Windows、Linux 桌面应用和移动端。不同方式对应不同使用额度，套餐额度不会叠加；具体以[官方计划与计费说明](https://cursor.com/help/grok-bot/plans)和账户页面为准。

1. 从 [x.ai/bot](https://x.ai/bot) 下载对应系统的 Grok Bot 应用。
2. 打开应用，用 Cursor 账户登录；如使用 SuperGrok 订阅，按提示关联账户。
3. 在侧边栏选 **New**，然后创建一个新 Bot；也可以从推荐 Bot 开始。
4. 给它设置名称、主要工作和工作规则。
5. 先分配一个不涉及外部修改的小任务，检查结果和权限请求。

### 一个 Bot 负责一类稳定工作

避免把所有任务都塞给一个“万能助手”。当目标、资料来源、工具权限或审批规则不同，就创建不同 Bot。例如：

- **资料研究员**：找资料、记录来源，不发布内容。
- **周报整理员**：读取指定数据，生成简报，不向团队发消息。
- **代码排查员**：复现问题、整理文件路径，不改生产环境。

Bot 的简介适合放长期有效的职责和边界；当前这一次任务的材料与交付要求写在消息里。Bot 可以记住稳定偏好和过往工作摘要，但重要决定仍应要求它检查当前的权威来源。

## 3. 怎样描述一个任务

官方入门文档建议在任务中交代结果、信息来源、限制、交付内容和审核节点。可以直接复制这个模板：

```text
目标：最后要完成什么？
来源：请读取哪些应用、文件、网页或对话？
步骤：先做什么，再做什么？
交付：我要看到什么文件、摘要、表格或草稿？
限制：哪些事情不能做？哪些动作必须先问我？
核对：请附来源链接、文件名或截图，并列出没能确认的事项。
```

**示例：**

```text
请读取我附上的项目复盘 PDF，整理成一页摘要。
列出已确认的结论、对应页码、未解决的问题和建议的下一步。
不要修改原文件，也不要把内容发给任何人。
如果材料没有证据，请标注“未说明”，不要推断。
```

任务做完后，先核对交付物、来源和 Bot 实际完成的操作；再用具体反馈让它修改，例如：“保留结论，把每条结论补上来源链接，并把推测单独放到一节。”

## 4. 连接应用并处理文件

### 连接应用

从侧栏打开 **Connect apps**，选择可用连接器并完成认证。开始任务时，可以在对话中输入 `@` 来引用 Bot、群聊、Routine 或连接器；输入 `/` 可以引用已保存的 Skill。官方建议：有连接器时优先用连接器处理对应服务；连接器不支持的操作再考虑使用浏览器或云端电脑。[应用与云端电脑指南](https://docs.x.ai/grok-bot/computer-and-apps)

### 附加文件

可以把文件拖入消息框，或点击附件按钮。官方列出的常见格式包括图片、音频、视频、PDF、文本、Word、Excel、PowerPoint、CSV、JSON、YAML、源代码、HTML、邮件文件和 Jupyter Notebook。桌面端一次最多添加 6 个附件；文档、图片和音频单个最大 25 MB，视频最大 200 MB。加密、损坏或特殊格式文件可能无法读取。[文件与结果指南](https://docs.x.ai/grok-bot/files-and-results)

写清楚每个附件是什么、应该如何使用，并说明不要修改原件。对重要结果，要求它提供来源链接、文件名、时间戳、截图或操作记录，以便复核。

## 5. 让多个 Bot 协作

当任务确实需要不同专长时，可以建立群聊，选择 2 到 6 个 Bot，并明确每个 Bot 的分工和交接内容。比如：

```text
@研究员 找出官方资料，给每个结论附链接。
@撰稿员 只根据已核实资料写中文初稿。
@校对员 对照来源检查事实和遗漏。
最后把草稿和问题清单发回本对话。不要发布内容。
```

从一支小团队开始：先让一个 Bot 负责完整结果，只有在专业职责固定时再增加 Bot。群聊能显示 Bot 之间的交接，但最终内容仍需要你检查。[消息与协作指南](https://docs.x.ai/grok-bot/chat-and-collaboration)

## 6. 把重复工作变成 Skill 和 Routine

- **Skill** 保存“怎么做”：步骤、判断规则、输入要求、输出格式、验证方式和审批边界。
- **Routine** 保存“何时做”：让某个 Bot 按日程，或在支持的事件触发时运行工作流。

先手动完成一项任务，修正到结果稳定，再让 Bot 把流程保存为 Skill；确认 Skill 可靠后，再创建 Routine。创建 Routine 时写清执行 Bot、时区、数据源、期望结果、异常时怎么处理，以及哪些动作需要审批。先用安全输入测试，检查它是否选用了最新数据、是否遵守停止点，再启用自动运行。[Skills 与 Routines 指南](https://docs.x.ai/grok-bot/skills-routines-and-automations)

例子：

```text
每个工作日早上 9 点，读取当前的项目进度表，
生成包含“已完成、风险、需要我决定”的中文简报并发到本对话。
不要编辑源表格、联系项目成员或发布消息。
如果数据源无法访问或数据不是今天的，请报告问题，不要沿用旧数据。
```

Routine 的测试运行也会执行真实操作，可能访问网站、改文件或调用连接器。测试前使用安全数据，并将写入或外部发送操作设置为需要审批。

## 7. 设置审批边界，保护账号和数据

这部分对 Grok Bot 尤其重要，因为它可以在云端电脑中使用浏览器会话和其他工具。

- **所有 Bot 共用一台云端电脑。** 浏览器 Cookie 和登录会话、文件、命令行凭据都可能被同一账户下的其他 Bot 使用。不要在云端工作区放入你不希望其他 Bot 访问的秘密。
- **不要把密码或一次性验证码发在聊天里。** 需要登录时，通过应用提供的接管流程由你自己完成。
- **外部动作写明必须停下等你。** 例如发送消息、发布内容、付款、删除文件、改权限或变更生产系统。
- **审批前检查目标和效果。** 如果看不懂 Bot 要执行的操作，先让它用普通语言解释，或要求先生成草稿。审批不会撤销已经完成的步骤。
- **定期复核连接器和 Routine。** 确认它们读取的资料仍然必要、日程和时区正确、失效时会报告而不是使用旧数据。
- **检查 Bot 模板是否包含内部信息。** 公开分享模板时，任何拿到链接的人都可能看到 Bot 的名称、简介、Skills 和 Routines 配置；先清除 API Key、客户资料和内部地址。

官方提供 Auto Review 审批控制和隐私设置，详见[审批、安全与隐私](https://docs.x.ai/grok-bot/approvals-security-and-privacy)。安全边界应同时写在任务、Bot 简介和自动化规则中。

## 8. 一套从试用到稳定运行的流程

1. 选一个低风险、重复性明确的任务。
2. 为它创建一个职责清楚的 Bot。
3. 在任务中写明来源、结果、限制和审核节点。
4. 先要求草稿或只读结果，检查证据和文件。
5. 用具体反馈修订，直到流程稳定。
6. 把稳定步骤保存为 Skill。
7. 确认异常处理和审批规则后，再设置 Routine。
8. 通过运行记录检查数据是否最新、结果是否可复核、动作是否停在正确的审批点。

记住：Bot 适合替你完成流程化工作，但它的记忆不能代替最新来源，自动化也不代表不需要监督。结果越重要，来源、预览和审核就越要明确。
